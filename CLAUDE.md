# Mochi Life

## Rules

- Read `docs/ARCHITECTURE.md` at the start of every session, before making changes.
- Every time you save a working version to GitHub, update README.md in the same
  save so it matches what the app currently does. List only features that are
  built and working; anything not built yet goes under "What's planned next".
- Update `docs/ARCHITECTURE.md` and `README.md` in the same commit as any change that
  affects them.
- Follow the conventions recorded in `docs/ARCHITECTURE.md`. If a requested change
  conflicts with them, state the conflict before proceeding.
- Keep verification minimal: confirm a clean build (no errors or warnings). Do not run
  simulator walkthroughs or UI tests unless asked.
- The user is not a software engineer. Final reports to the user are written in plain
  language, with a short manual test checklist for the iPhone Simulator (iPhone 18 Pro).
